# Accessibility and Print Review

配色审查必须针对“实际图形 + 实际尺寸 + 实际导出格式”。色板本身只能提供初步信号。

## 最小检查

1. **相邻元素**：检查并排条形、点、填充和图例中的相邻颜色，而不是只看色板圆点。
2. **文字对比**：浅色填充使用深色文字；深色填充使用白字或更亮的文字。对比度不足时先改文字/描边，再改色相。
3. **灰度**：导出灰度预览，确认关键组别至少还能通过明度、标签、形状或线型区分。
4. **色觉差异**：至少查看红绿色觉差异和蓝黄色觉差异模拟；若关键信息只剩颜色，补充直接标签或形状。
5. **印刷**：检查 PDF/PNG 在目标尺寸下的细线、浅填充、透明度和叠加效果；不要把显示器颜色当作印刷证明。
6. **缩印**：按论文栏宽或补充图尺寸查看；长标签、图例和浅色小点必须仍可识别。
7. **跨面板**：同一变量全图使用同一个命名颜色；图例顺序和正文描述保持一致。

## 艺术风格的专项检查

艺术性应体现在色相关系、明度节奏和有限的强调上，而不是增加不可读的装饰。对每套风格再检查：

1. **焦点数量**：是否只有一个主要视觉焦点？如果每个类别都使用高饱和色，风格已经变成噪声。
2. **角色分离**：背景、文字、描边和数据填充是否来自不同角色？不要让背景色同时代表一个组别。
3. **明度骨架**：转为灰度后，主组、支持组和背景是否仍有至少两层可辨别的明度关系？如果没有，补充形状、线型或直接标签。
4. **文化标签边界**：`敦煌`、`宋韵`、`水墨`、`Nature`、`Cell` 等只描述视觉语汇或克制目标，不写成历史复原、官方色板或期刊要求。
5. **密度适配**：密集图减少颜色数量和透明叠加；稀疏的大色块可以使用更丰富的色相，但仍要在目标尺寸查看。

## 诊断记录建议

把以下信息与图或脚本一起保存：

```text
palette_id: <atlas id or custom id>
original_palette: <if adapted>
adjustment: <lightness / chroma / hue / none>
figure_size: <width x height in mm or inches>
export: <PDF/SVG/PNG/TIFF, RGB/CMYK if known>
audit_tool: <name and version, or unavailable>
human_review: <final-size color / grayscale / CVD / print proof>
```

`CIE L*` 差异、相对亮度对比度和色觉模拟都只是诊断信号。填充、边界、透明度和背景会改变实际结果；不要把单个阈值写成色盲认证或期刊合规证明。

## 推荐做法

- 定性分类一般不超过 5–7 个颜色；更多类别优先用直接标签、分面或形状。
- 连续色带保持明度单调；发散色带先定义有意义的中点，不要默认把“白色”解释成无效。
- 对重要组别使用色相和明度的双重差异；不要只用一组相近的粉色或蓝色。
- 白底科研图默认使用深灰 #263238 作为正文和轴线，避免纯黑造成过硬的视觉重量。
- 对浅色填充加深色细描边可以提高缩印稳定性，但描边不能遮住数据。
- 在 R 中用命名向量，在 Python 中用字典；不要依赖 scale_fill_manual 或字典插入顺序的隐式重排。
- 对同一语义建立一个全局颜色对象，在每个面板显式调用；不要在各面板中重新生成或按出现顺序截取色板。
- 用透明度表达不确定性或重叠时，先在白底和灰度中查看叠加结果；透明度不能代替类别编码。

## 自动化诊断边界

如果本机存在 EasyPlot 的 palette audit，可以把最终渲染图和色板交给它检查。报告应保留工具版本、输入图尺寸和导出格式。没有工具时可以给出人工检查清单，但必须把自动化结果写为 unavailable，不能补写一个分数。

自动诊断通过不等于期刊合规、色觉无障碍或印刷无风险；诊断失败也不一定说明整套图不可用，需要回到实际图形语义和几何。
